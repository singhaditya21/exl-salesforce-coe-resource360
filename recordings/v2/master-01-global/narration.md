# Master 01 — Global Entry, Home and Access

## Intro

Welcome to the first master recording for EXL Salesforce COE Resource 360. This walkthrough covers the six global screens that establish identity, access, navigation and user context before any staffing or delivery transaction begins. Every product view in this recording comes from the authenticated Salesforce Developer Org and uses the visible Resource 360 screen rail. The recording contains only fictional, sanitized demonstration data. We will cover EXL entry assurance, the role-aware home, notifications, governed cross-object search, effective role and portfolio scope, and user preferences with in-product help. Together, these screens demonstrate how Resource 360 provides one governed front door for the eighteen business personas supported by the product, while Salesforce remains the system of record.

## GLB-01 — EXL SSO entry

We begin at GLB-01, the EXL SSO entry and federated-entry assurance screen. In the production design, this is the boundary where EXL identity would be verified by the enterprise identity provider. For this demonstration, the Salesforce Developer Org supplies the authenticated identity, while the product still shows the intended assurance contract. The user is not trusted merely because a browser route is open. Resource 360 resolves the Salesforce user, assigned permission-set groups, effective business role and authorized portfolio scope on the server. The screen distinguishes the demo authentication mechanism from the production SSO integration so there is no false claim that enterprise SSO is already connected. The Continue with EXL SSO action represents the governed entry point. The workbench below records the identity context, status and supporting evidence that would be available for audit. Unauthorized or expired scopes are handled as explicit states rather than silently widening access.

## GLB-02 — Role-aware home

The next selection in the screen rail is GLB-02, the role-aware home. This is the first operational landing page after identity and scope are resolved. The headline measures are not decorative: they are derived from the seeded Salesforce data. The current baseline shows all sixty active delivery resources at eight or more planned hours, fifty resources exactly balanced at eight hours, and ten controlled over-allocation cases. It also surfaces approved revenue, weighted gross margin and the billable mix. Below the summary, the home explains the authorized roles, the server contract and the workflow evidence expected for this route. The primary action changes with the acting persona. A staffing user is directed toward staffing demand, a project manager toward planning and delivery work, an approver toward decisions, and an executive toward governed insight. The screen therefore reduces navigation noise while preserving the same underlying Salesforce records and security model.

## GLB-03 — Notification center

GLB-03 is the governed notification center. A useful notification is more than a message badge, so the product preserves the trigger, severity, owner, first-seen time and closure evidence. The live workbench shows notification categories tied to the Resource 360 operating model, including staffing, budget, credential, schedule and timesheet exceptions. Users can distinguish informational signals from warnings and critical items, then follow the associated business context. Read and closure state are designed to be auditable, which prevents important exceptions from disappearing without ownership. Because the notification query executes in Salesforce user mode, the user sees only notices that are valid for the effective role and record scope. The same rule applies when notifications lead to another screen: a notification cannot become a back door into an engagement, resource or commercial record the user is not allowed to view. This creates a dependable exception inbox for daily operations rather than a generic alert feed.

## GLB-04 — Global search

We now move through the visible navigation to GLB-04, global search. Resource 360 search is cross-object but governed. It brings together engagements, accounts, contracts, resources, staffing requests, allocations, work units and other operational records without flattening their security boundaries. The screen shows the search action, a result context and the evidence state used to explain why an item is visible. Search results are evaluated against the authenticated user, effective business role and assigned portfolio scope. Sensitive commercial information therefore remains restricted even when a matching name or identifier exists elsewhere in the org. The intended experience is fast discovery with predictable access: users can search once, understand the object and context, and continue into an authorized three-sixty view or workbench. Empty, filtered-empty, unauthorized and failure conditions are represented deliberately so a user can distinguish no matching data from data hidden by policy. This is especially important for a COE solution shared across multiple accounts, portfolios and sub-portfolios.

## GLB-05 — Role and scope switcher

GLB-05 controls the effective role and scope for the active session. Resource 360 supports eighteen business personas, represented in the constrained demo org through controlled composite users and permission-set groups. A user may hold more than one certified business role, but the browser cannot invent or elevate that role. The server validates the requested role, portfolio, sub-portfolio and any time-bound delegation before applying the context. This screen makes that active context visible, so actions and metrics can be interpreted correctly. A portfolio manager can work across the permitted portfolio, while a project manager is constrained to the engagements and records granted to that context. Finance and approver roles receive their own controlled authority. Applying a scope creates correlated evidence, and negative access remains testable: selecting a label is not enough to obtain records or execute a workflow. This approach makes persona demonstrations practical while preserving the principle that Salesforce authorization, sharing and user-mode queries remain authoritative.

## GLB-06 — User preferences and help

The final global screen is GLB-06, user preferences and help. It combines personal display choices with Salesforce-native guidance for the most important journeys. The walkthrough library covers staffing decisions, budget and actuals, demo activation and related operating paths. Preferences are saved as user context rather than as global configuration, so one person’s display or guidance settings do not affect another persona. The screen also establishes the accessibility baseline for the recording programme: keyboard-operable actions, meaningful labels, visible focus, captions and reusable narrative guidance. Help content is tied to governed screens instead of sending the user to an unrelated generic response. This matters in a product with more than one hundred routes because a user should receive guidance for the screen, role and task currently in view. In a production EXL deployment, support links and policy content can be configured without changing the core navigation contract.
